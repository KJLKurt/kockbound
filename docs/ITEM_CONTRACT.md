# Shared item contract — first playable increment

Simulation/protocol/content IDs now end in **0.8.0**, rejecting older room clients. This is a cross-boundary schema change: `MatchConfig.items?: ItemId[]` selects registered items; optional `World.items` carries next spawn tick, serial and ground/projectile entries; `Player.heldItem` is one slot and `stunnedUntil` is authoritative active-tick time. Definitions are in shared/content/items.ts; no executable configuration is accepted. Optional item `activated` preserves a passive item's original expiry through drops and transfers.

Input adds optional boolean `useItem` and `dropItem`; unknown fields and malformed values are rejected. Server coalescing preserves pending action edges, neutralization clears them, stale sequence rules still apply. Only accepted commands reach item simulation. Client movement prediction disables speculative item simulation; pickups, blasts and stuns come from snapshots. Snapshot parsing validates item kinds, IDs, finite spatial fields, owners and bounded lists. Room-create APIs accept optional validated `items` alongside humanCount; clients cannot change them during a round.

Cloud bomb defaults: first spawn after 4 active seconds, subsequent attempts every 8 seconds, maximum five ground objects at spawn; seeded random location inside the remaining disk. An empty-handed live player within 0.85 m picks up automatically. Bombs have a five-second live fuse from spawn, including while held. Toss travels at 6 m/s and detonates one second after toss; thrown bombs cannot be repicked. Drop preserves remaining fuse and blocks that dropper from pickup for one second. Blast radius 3.5 m; base push 10 with distance falloff and existing vulnerability, capped by simulation; stun 0.6 s. Self-hits are possible; external hits/knockouts credit their source. Dead holders currently lose the held item. These are reversible tuning defaults, not final balance approval.

Rendering shows a blue/gold orb, blinking last-two-second shell and last-one-second blast area; reduced motion preserves a static visible shell and area. Toss/drop HUD uses E/Q and touch targets. Saved master/item toggles apply to the next solo match or newly hosted room. Both default enabled for this playful preview. Bots seek safe nearby pickups, throw held bombs and avoid imminent ground blasts using ordinary inputs.

Registered passives: Push shovel lasts 12 seconds from first pickup, adding one forward-cone hit per dash within 1.5 m plus target radius; Big mode lasts 10 seconds, changes authoritative radius from 0.45 to 0.65 m and mass to 1.8, reducing incoming push and affecting collision separation; Helicopter hat lasts 30 seconds and consumes itself on one fall, returning to the inner edge with 0.5 seconds of recovery. Server forfeits bypass rescue. Passives work while held, share the one slot, and can be dropped. Ground passives expire after 20 seconds before first pickup; activated transfers never refresh lifetime. Their models blink near expiry, with a static reduced-motion alternative. Big presentation scales to 1.45 and raises its camera/label; gameplay changes belong to this temporary item, never cosmetics.

Next: mystery crate/remover, shared support tiles and optional hazards, and the extra interactive danger. Seven registered items have independent saved toggles; spawn selection is seeded from enabled IDs. Actual phone and full interaction/telegraph/balance review remain required.

Ranged increment (D45): Bubble blaster has five shots, 0.4-second cooldown, speed 16 m/s, range 18 m, radius 0.22 m and base push 3 (dash baseline 7). Wind has one piercing shot at 24 m/s, range 24 m and radius 1.1 m; base push falls linearly from 14 to 7 over travel. Rolling rock has one piercing roll at 8 m/s, range 24 m and radius 0.85 m, base push 8 and one-second flatten/stun. Each piercing projectile hits each opponent once; owners are excluded. Vulnerability and temporary mass apply normally. Swept circle/player and expanded obstacle ray tests prevent tunnelling; obstacles stop every ranged shot. All ranged pickups expire after 20 seconds held; charges/cooldown/expiry survive transfer.

Optional HeldItem charges/readyAt and ItemState.shots are authoritative snapshots, validated and bounded (64 projectiles maximum); optional Player.flattenedUntil drives visual squash only while the matching authoritative stun prevents actions. Accepted Fire inputs use current command direction, otherwise last facing. Event shot triggers an original-bank cue; projectile shapes and flat pose are code-authored. Snapshot/schema compatibility now requires 0.4.0. Remaining crate/remover/additional danger and tiles/hazards are still required.

Version 0.5.0 also registers Platform remover (eight total selectable items); its targeting, timing and support behavior are defined in TILE_CONTRACT.md. Previous version paragraphs above describe their increments, not the current compatibility ID.

Version 0.6.0 registers Mystery crate as a ground-only object. Actual dash movement within 1 m opens it once, emits crateopen and reveals a seeded other enabled item. No proximity pickup of the box; full hands leave the revealed item on the ground. Bomb reveal starts a fresh five-second fuse, other reveals a twenty-second ground lifetime. Unopened crates expire after twenty seconds. Crate-only configuration spawns nothing; the UI explains another item must be enabled. Nine catalog choices now implemented; optional hazards and extra interactive danger remain required.

Version 0.8.0 adds Spring pod, the tenth registered choice and additional interactive danger; see POD_CONTRACT.md. Hazard selection/state arrived in 0.7.0 (HAZARD_CONTRACT.md). All compatibility IDs now end 0.8.0.
